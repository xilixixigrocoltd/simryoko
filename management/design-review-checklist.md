# 设计评审 Checklist

**用途**: 设计稿交付前检查  
**时间**: 每周五 16:00  
**参与**: UI + 前端 + PM

---

## 评审流程

```
时间: 60分钟

1. UI展示 (20分钟)
   - 设计稿演示
   - 交互说明

2. 开发评审 (20分钟)
   - 可实现性评估
   - 技术难点讨论

3. 确认决策 (20分钟)
   - 确定下周优先级
   - 记录待解决问题
```

---

## Checklist

### 视觉检查 (UI负责)

- [ ] 色彩使用符合设计系统
- [ ] 字体层级正确
- [ ] 间距一致
- [ ] 圆角统一
- [ ] 阴影效果合适
- [ ] 图标风格一致
- [ ] 图片质量达标

### 交互检查 (UX负责)

- [ ] 用户流程完整
- [ ] 交互状态齐全
- [ ] 动效说明清晰
- [ ] 响应式版本完整
- [ ] 错误状态设计
- [ ] 加载状态设计
- [ ] 空状态设计

### 技术评审 (开发负责)

- [ ] 设计可实现
- [ ] 无技术难点
- [ ] 性能影响可控
- [ ] 响应式可行
- [ ] 动画可实现
- [ ] 浏览器兼容
- [ ] 无障碍支持

### 业务检查 (PM负责)

- [ ] 符合产品需求
- [ ] 用户体验流畅
- [ ] 转化路径清晰
- [ ] 品牌调性一致
- [ ] 竞品差异化
- [ ] 可测试验证

---

## 评审输出

### 通过标准

```
全部检查项通过 → 进入开发
```

### 有条件通过

```
小问题修复后进入开发
→ 记录问题清单
→ 指定修复时间
→ 开发可并行开始
```

### 不通过

```
重大问题需重新设计
→ 记录问题
→ 确定重做范围
→ 调整排期
```

## 常见问题

### 设计无法实现

```
问题: 某个动效技术难度高
解决:
1. 讨论替代方案
2. 评估简化版本
3. 或延期到后续版本
```

### 设计与需求不符

```
问题: 缺少某个功能
解决:
1. 确认是否必要
2. 必要 → 补充设计
3. 非必要 → 记录为后续优化
```

### 响应式遗漏

```
问题: 只有Desktop版
解决:
1. 必须补充Mobile版
2. 可延期2天
3. 开发先做Desktop
```

## 评审纪律

### Do
- [ ] 提前准备，不临时看稿
- [ ] 聚焦问题，不发散讨论
- [ ] 记录决策，不口头约定
- [ ] 确定时间，不无限延期

### Don't
- [ ] 不要边设计边评审
- [ ] 不要跳过技术评审
- [ ] 不要没有结论结束
- [ ] 不要评审后大改设计
